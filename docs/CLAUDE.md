# CLAUDE.md — docs/

You are working in the Astro Starlight documentation site (`docs/` directory). pnpm is
isolated to this directory; do not traverse into the parent uv/Python workspace.

## Scope rules (PLAN §8)

- **Concept + how-to only.** These pages explain ideas and walk through tasks. They never
  duplicate ADR content.
- **ADRs are source-of-truth in `/adr`.** The `adrs/` pages here are a read-only mirror
  generated by `scripts/sync_adrs.py`. Never hand-edit them — edit `/adr` and re-sync.
- **Examples before reference.** Every page opens with a runnable example or concrete
  walkthrough before any reference tables.
- **Max H3 depth.** Do not nest headings deeper than H3 (`###`). Keep structure flat.

## Architecture

- Astro + Starlight, static-first.
- Mermaid diagrams via the `astro-mermaid` integration — it MUST come before `starlight`
  in the integrations array.
- AI-friendly docs via `starlight-page-actions` and `starlight-llms-txt`.
- Search defaults to Pagefind.

## Content conventions

- Prefer Markdown over MDX unless a component (Card, Tabs) is required.
- Frontmatter for `title`, `description`, sidebar ordering.
- Put prerequisites before steps; exact commands in fenced code blocks.
- Use Starlight aside syntax (`:::note`, `:::tip`, `:::caution`, `:::danger`).
- Prefer file-based (autogenerate) navigation over hardcoded sidebar entries.

## Commands

- `pnpm dev` — local dev server
- `pnpm build` — production build
- `pnpm preview` — preview built site

## Guardrails

- **Do not switch docs frameworks** unless explicitly asked.
- Do not introduce SSR, React, or other UI frameworks without a concrete need.
- Do not add unnecessary client-side JavaScript.
- Keep pages mostly Markdown-native for high-quality copy-as-markdown.
