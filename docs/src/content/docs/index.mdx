A code-analysis agent that **reads code semantically, runs experiments in a
throwaway sandbox, and verifies hypotheses in a closed loop**. The agent has
three faculties:

- **Eyes** — Claude Opus 4.8 on Amazon Bedrock reads the target repo
  (lexical + AST + cross-reference search).
- **Hands** — a per-experiment Docker / gVisor sandbox launched with
  `--network=none` by default.
- **Memory** — an append-only hypothesis board, a durable findings ledger,
  and a tamper-evident audit log.

The differentiator over a Static Application Security Testing (SAST) flood is
that the agent **falsifies its own guesses by running them**: a candidate bug
stays a hypothesis until the sandbox produces a Proof of Concept (PoC) or a
counter-example, and only confirmed findings reach the ledger.

## What v1 does

The v1 implementation is the **pull-request reviewer**. Given a diff, it
loads the target repo and a hand-written `threat-model.yaml`, runs the diff
through Claude Opus 4.8 with a deny-by-default tool gate and a sandboxed
exec surface, scores each candidate on three axes (pattern, recall,
reachability), dispatches accordingly (specialized worker, parallel shell,
or swarm), and emits confirmed findings as Static Analysis Results
Interchange Format (SARIF) v2.1 plus a hash-chained
Write-Once-Read-Many (WORM) audit-log line per tool call.

```sh
mise run dev
# pr-reviewer review ./apps/pr-reviewer/fixtures/tiny-repo
```

The pull-request mode is the first of [five lifecycle modes](/agentic-security-lab/concepts/lifecycle-modes/)
the substrate is designed for. The other four (Onboarding, Nightly variant,
Release, Incident) reuse the same six packages — adding one is new
orchestration wiring, not new isolation, ledger, or audit primitives.
